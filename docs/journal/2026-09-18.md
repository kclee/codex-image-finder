# Image Finder development journal — 2026-09-18

## Bounded local semantic subtitle-search trial

### Purpose and scope

Completed the smallest useful experiment for determining whether semantic search over
existing OCR subtitles helps find real screenshots when the remembered meaning differs
from the wording. This is an additional command-line capability, not a replacement for
the existing exact/partial/OpenCC search and not part of the PySide6 UI.

The experiment embeds only OCR `subtitle_text`. It does not decode or analyze image
pixels, create vision embeddings, recognize faces, classify moods, start a service, or
process the full archive. The source collection at
`C:\Users\kckck\Desktop\Output` remained untouched.

### Engine and model

- Engine: FastEmbed 0.8.0.
- Runtime dependency: ONNX Runtime 1.29.0, CPU.
- Requested model: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`.
- Actual ONNX source: `qdrant/paraphrase-multilingual-MiniLM-L12-v2-onnx-Q`.
- Exact cached revision: `faf4aa4225822f3bc6376869cb1164e8e3feedd0`.
- Model file: `model_optimized.onnx`, 235,052,644 bytes.
- Dimensions: 384.
- Pipeline: `ocr-subtitle-semantic-v1`.
- Parameters: latest OCR subtitle only; deterministic content-SHA-256 ordering; maximum
  50 identities; 512-token maximum; mean pooling; no query/document prefix; L2
  normalization; cosine similarity; little-endian float32 storage.

FastEmbed reports that version 0.8.0 uses mean pooling for this model. That behavior is
therefore explicit in the versioned parameters rather than left as an unstated library
default. The adapter also verifies installed FastEmbed/ONNX Runtime versions and the
cached model revision before use, and runs with local files only.

### Selection and rebuild boundaries

The selector opens `data\image-finder.sqlite3` in SQLite read-only mode. It chooses the
latest OCR result for each present stable image identity, discards identities whose
latest result has no subtitle, sorts by exact image content SHA-256, and takes no more
than 50. It does not fall back to an older non-empty subtitle when the newest OCR result
is empty.

The separate derived index is `data\semantic-subtitle-trial.sqlite3`. Its run metadata
records engine/runtime versions, model name/source/revision, dimensions, index schema,
pipeline, and parameters as JSON. Its manifest hashes each selected image ID, current
relative path, and subtitle SHA-256. A relevant spec change creates a different run ID;
a source, path, or selection change changes the manifest. Matching data is reused,
while `--rebuild` explicitly regenerates it. The current small experiment retains only
the active derived run, so the database is wholly disposable.

SQLite, JSON metadata, SHA-256, ONNX, and ordinary little-endian float32 blobs keep the
persistence language-neutral. A future F#/.NET implementation can read the same data
with standard SQLite and binary APIs. The only Python-specific layer is the current
FastEmbed inference adapter; it is not serialized into the index.

### Evaluation

What worked well:

- paraphrases and conversational intent when a relevant subtitle existed;
- Chinese/English cross-language retrieval;
- low steady-state latency and tiny per-item vector storage;
- clear, deterministic, fully rebuildable metadata and source hashing;
- no change to exact/partial search or the desktop UI.

What worked poorly:

- concepts absent from the 50 subtitles still receive plausible-looking positive
  scores, so cosine score alone cannot prove relevance;
- short ambiguous reaction words such as `傻眼` can match a lexical neighbor rather
  than the intended reaction;
- OCR noise, mixed Chinese/Japanese text, sticker text, and non-drama items distort
  rankings;
- subtitle-only embeddings cannot infer a face, visual reaction, person, object, or
  scene mood that the subtitle does not state;
- the deterministic content-hash sample is reproducible but not representative of every
  topic in the archive.

Conclusion: 384-dimensional multilingual MiniLM subtitle embeddings are promising as a
secondary discovery tool for meaning, reaction, conversational situations, and English
queries against Chinese/Japanese subtitles. The experiment is not sufficient to choose
a global score threshold or embed the full archive. A next product decision should be
based on more user-entered queries against a larger but still controlled subtitle set,
not on adding visual analysis or changing application architecture.

## Representative 1,000-subtitle evaluation

### Goal and fixed boundaries

Expanded the completed 50-item experiment to determine whether subtitle semantic search
remains useful against a substantially larger portion of the real OCR catalog. The
model, 384-dimensional representation, source-text-only boundary, language-neutral
SQLite/JSON/float32 storage, and source-image read-only rule remain unchanged. No UI,
vision analysis, classifier, server, or full-archive embedding was added.

The fixed query set was written to `semantic-evaluation-queries.json` before the run. It
contains all twelve requested intents plus four general conversational/situation probes:
`鼓勵別人振作`, `拒絕別人的要求`, `生氣警告別人`, and `想休息`. It is now a
versioned baseline for comparing future models or ranking experiments.

### Catalog and sampling strategy

The catalog contains 2,309 present identities whose latest OCR result has a non-empty
subtitle. The evaluation selected exactly 1,000 using deterministic proportional
stratification:

1. Group by the top-level component of the current relative path.
2. Give every non-empty group at least one slot.
3. Allocate remaining slots proportionally using deterministic largest remainders.
4. Within each group, select by exact image content SHA-256 order.

This is not a newest-files sample, and it preserves both large year/category groups and
small categories.

### Experimental hybrid method

The existing full-catalog exact/partial/OpenCC search was left unchanged. For a fair
hybrid comparison, the same lexical substring/OpenCC logic was also applied within the
1,000-item sampled index. Semantic and sampled lexical rankings were combined using
equal-weight reciprocal-rank fusion:

`hybrid score = 1 / (60 + semantic rank) + 1 / (60 + lexical rank)`

A missing side contributes zero. RRF uses rank rather than pretending cosine similarity
and lexical scores share a calibrated scale. This is an experiment, not a production
ranking decision.

show meaning-based results as a separately labeled section or mode.

### Evaluation and architecture implications

Increasing from 50 to 1,000 made semantic search clearly more useful because relevant
targets were present for more real intents. It also exposed more high-scoring false
positives. The model is useful for paraphrases, cross-language retrieval, short
reactions, and conversational situations, but struggles with:

- direction and roles (`comfort someone` versus `someone is distressed`);
- negation/opposites (`不想上班` versus `我想要工作`);
- ambiguous short reaction terms;
- one keyword dominating a multi-part intent;
- OCR noise and mixed-language text;
- concepts or visual states that subtitles do not state.

Multilingual MiniLM remains an appropriate compact baseline: local startup, query
latency, storage, and cross-language behavior are all practical. Testing another
multilingual text model is now justified before production ranking, specifically to see
whether it improves intent direction, negation, and short Chinese reactions. That
comparison should reuse this fixed sample and query set rather than replacing the
current baseline.

The result is useful enough to justify an eventual explicitly labeled semantic-search
mode or secondary result section, but not replacement of exact/partial search, not an
automatic cosine threshold, and not UI work in this evaluation step.

F#/.NET interoperability remains straightforward. SQLite, JSON, SHA-256, ONNX, float32
vectors, cosine scoring, and RRF are language-neutral. A future implementation must
reproduce the tokenizer, 512-token truncation, mean pooling, and L2 normalization to
match vectors exactly; Hugging Face tokenizer compatibility around the quantized ONNX
model is the main inference-parity task. No Python object serialization was introduced.
