## Architecture and packaging decisions

### What

Selected Python for the complete first prototype while keeping F#/.NET as a possible
long-term implementation option.

### How

- PySide6 supplies one desktop window without a browser or visible server.
- SQLite stores portable, language-neutral persistent data.
- Scanner, catalog, analysis, and search modules do not use PySide6 types.
- Standard JSON, SQLite, hashes, and image files are preferred over Python-only
  serialization.
- The eventual Windows release will be a portable one-folder build: unzip and run,
  without separately installing Python.
- Windows is required; macOS remains desirable for a future version.

## Stable identity and versioned analysis

### What

Paths are locations rather than image identities, and analysis output is versioned.

### How

- Exact SHA-256 identifies unchanged content after a move or rename.
- `file_locations` retains current and historical paths with first/last observation.
- `analysis_runs` records analysis type, engine/model versions, pipeline version,
  parameters, and timestamps.
- `analysis_results` can retain multiple generations for later comparison.
- `derived_files` tracks rebuildable thumbnails and future artifacts separately.

### Verification

An automated test renames a sample image, rescans it, confirms that only one image
identity exists, and confirms that the old location becomes historical while the new
location is present.

## Full discovery and incremental scan

### What

Implemented and executed complete read-only discovery of the source library.

### How

- Recursively recognizes supported image extensions without following directory links
- Uses size and nanosecond modification time to reuse unchanged records
- Computes SHA-256 for new, changed, or newly located files
- Stores each path separately from its content identity
- Generates 480 by 270 maximum JPEG thumbnails under `data/thumbnails`
- Records scan runs, counts, completion state, and errors in SQLite
- Marks missing paths only after a directory walk completes without traversal errors
- Provides a UI-independent scanner plus a PySide6 background-thread adapter

- 3,334 unique image identities and thumbnails
- Zero errors
- Zero source paths marked missing

Immediate second pass:

- Zero files rehashed
- 3,337 unchanged files reused
- Zero thumbnails regenerated
- Zero errors

The difference between 3,337 locations and 3,334 identities means three locations share

## Virtual gallery startup optimization

### What

Removed the full-catalog startup delay caused by eagerly creating and decoding thousands
of thumbnail widgets.

### How

- Replaced `QListWidget` items with a `QAbstractListModel` and `QListView`.
- The model holds ordinary `SearchResult` records and supplies display text, tooltips,
  and icons only when Qt requests them.
- Thumbnail icons are decoded on demand and cached by their derived file path.
- Uniform grid item sizes let Qt calculate layout without measuring every image.
- Scanning, SQLite, identity, and search code were unchanged.

### Verification and result

- Same disposable database with 3,337 current locations
- Same offscreen application smoke-test procedure
- Before: 16.23 seconds
- After: 0.52 seconds
- Three automated tests passed, including the full-catalog one-result-per-location check
