## Architecture and packaging decisions

### What

Selected Python for the complete first prototype while keeping F#/.NET as a possible
long-term implementation option.

### How

- PySide6 supplies one desktop window without a browser or visible server.
- SQLite stores portable, language-neutral persistent data.
- Scanner, catalog, analysis, and search modules do not use PySide6 types.
- Standard JSON, SQLite, hashes, and image files are preferred over Python-only
  serialization.
- The eventual Windows release will be a portable one-folder build: unzip and run,
  without separately installing Python.
- Windows is required; macOS remains desirable for a future version.

## Persistent analysis queue

### What

Added the UI-independent persistence boundary required for OCR and future semantic
analysis to pause, survive an application exit, and resume without repeating completed
work. Removed the prototype-only OCR-trial import from normal startup.

### How

- `analysis_jobs` stores one job per image and versioned analysis run.
- Status is explicit: pending, running, succeeded, failed, or skipped.
- Claims use a short SQLite immediate transaction so two future workers cannot claim the
  same job.
- A startup recovery operation returns interrupted running jobs to pending.
- Successful completion writes the versioned result and job status in one database
  transaction.
- Completed results are excluded when the same analysis configuration is queued again.
- The queue selects one current location for an image identity, so exact duplicate paths
  are analyzed only once.
- No production image was processed and no real-library job was queued in this step.

### Verification and result

An automated test scanned two temporary images, queued two fake OCR jobs, claimed one,
simulated interruption, recovered and reclaimed it, completed it, and confirmed that the
completed result was not queued again. All four project tests passed. The full-catalog

## Explicit bounded desktop OCR controls

### What

Added desktop controls for small OCR batches, pause-after-current-image behavior,
failure retry, and visible progress without coupling the queue or OCR engine to Qt.

### How

- **OCR next 10** prepares at most ten pending jobs and starts a background worker.
- Existing pending work counts toward the ten-job cap; repeated clicks cannot silently
  grow the prepared queue while a batch is pending or running.
- PaddleOCR is imported and initialized inside the worker only after explicit action.
- **Pause OCR** sets a thread-safe event; the current image finishes transactionally and
  the remaining jobs stay pending.
- **Retry failed** is a separate explicit operation.
- The UI shows succeeded, pending, and failed counts and refreshes searchable results

- Analysis specifications moved into a lightweight module, so displaying queue status

## View-ordered OCR and Chinese script-equivalent search

### What

Made the meaning of the bounded OCR action predictable and added local Traditional /
Simplified Chinese search equivalence without changing stored OCR results.

### Previous behavior

- The old queue selected pending work by image creation timestamp and UUID. Because most
  images entered the catalog in one scan, its practical order looked arbitrary.
- A Traditional Chinese query did not find a subtitle stored only in Simplified Chinese.

### How

- Renamed the action to **OCR next 10 in view**.
- The UI sends the gallery's currently displayed stable image identities to the
  UI-independent queue in path order. Folder and search filters therefore define the
  eligible set.
- Existing pending jobs in that view resume first; succeeded, failed, running, and
  version-complete identities are not silently added. Exact duplicate file locations
  share one image identity and are analyzed once.
- The OCR worker may claim only identities from that bounded batch, so unrelated pending
  work cannot be drained accidentally.
- Added OpenCC 1.4.2 as a local query-time dependency. Search tries the original query
  plus `t2s`, `s2t`, `tw2s`, and `s2tw` equivalents.
- Raw OCR text is never rewritten. Script conversion can be changed later without an OCR
  rerun or database migration.
- The persisted **Last OCR batch** view now includes only succeeded or failed attempts,
  rather than showing unprocessed pending jobs as completed work.

### Verification and result

- All eight automated tests passed, including bounded ordering and Traditional-to-
  Simplified query expansion.
- A live Traditional query `你是在教訓我嗎` found
  `CN/capture-20190901-190209.png`, whose unchanged stored OCR is Simplified
  `你是在教训我吗`.

## Automatic incremental startup scan

### What

Connected the existing read-only incremental scanner to normal application startup so
new, changed, moved, and missing files can be discovered without a manual scan each time.
This does not start OCR.

### Startup rules

- The window and existing catalog appear first; the scan begins on the Qt event loop and
  runs in the existing background scan worker.
- Only the most recently registered library root is checked automatically. First launch
  with no registered library continues to wait for **Add / scan folder…**.
- If the saved folder is temporarily unavailable, the app stays open and reports it in
  the status bar rather than showing a blocking error dialog or marking files missing.
- OCR controls are disabled during discovery so scanning and image analysis do not write
  to the catalog concurrently. Search and the already-loaded gallery remain available.
- Manual scans still show a blocking error dialog when they fail; automatic failures are
  reported non-modally in the status bar.
- Diagnostic `--smoke-test` startup deliberately suppresses automatic scanning.
